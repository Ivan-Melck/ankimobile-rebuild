# Architecture

The default app uses UIKit navigation and WKWebView card documents over the full pinned Anki backend. `AnkiAppState` owns one real `AnkiCollection`, profile-scoped model preferences and Keychain authentication. Each profile has its own `collection.anki2`, media folder and media database. Imports create new profiles and preserve existing ones.

`AnkiBackend.swift` sends lossless protobuf JSON through a small C ABI. `full_backend.rs` reflects the fork’s generated service catalog and forwards calls to `Backend.run_service_method`; it does not translate collection objects through the original rebuild’s data model. Protobuf int64 values remain decimal strings. The backend registry lock is released before operations, allowing concurrent progress/cancellation during sync.

`Vendor/anki` pins the complete public fork. Its Rust collection owns schema migration, scheduling, search, rendering, package import/export, SQLite transactions and sync. Shared backend changes stay in the public fork; mobile adapters live outside the submodule. `scripts/prepare-backend.sh` initializes the backend and its translation dependencies. Protobuf descriptors are embedded at build time.

`collection_rwkv.rs` loads the actual fork inference runtime, consumes canonical history/input-row RPCs and publishes candidate scores back to the Anki queue builder. IDs are preserved; nonnumeric preset IDs use the desktop’s Blake2b mapping. Canonical history changes invalidate derived state after answers, import, sync or undo. No neural state replaces review history. Curve intervals pass through backend scheduling-state construction; S90 is applied only when Curve is enabled. Model and precision are local profile settings and must match desktop settings for parity. See the unresolved parity cases in [compatibility](compatibility.md).

The native reviewer accepts prepared backend states, renders backend HTML and CSS, and submits the chosen state to `AnswerCard`. Template JavaScript is enabled. A disposable viewer directory contains hard links to regular media files (copy fallback) and the rendered HTML; [WebKit file loading](https://developer.apple.com/documentation/webkit/wkwebview/loadfileurl(_:allowingreadaccessto:)) grants read access only to that directory. Collection databases and authentication files are excluded. Bundled MathJax and the fork’s image-occlusion canvas renderer run offline; cached LaTeX uses backend-generated media names. Audio tags retain their question/answer side and play sequentially with native TTS; the restricted message bridge exposes reveal/replay, never sync credentials or arbitrary backend calls. External links open in the system browser. Rendering runtime gaps are documented separately from collection preservation.

The original JSON implementation remains accessible as a separate local collection, and existing JSON data is retained. Its `CollectionStore`, `StudyPlanning` and scheduling C ABI support the earlier reconstruction and simulation screens. They are not used to schedule imported real Anki collections. The legacy UI test launch flag still tests those flows; `--anki-testing` creates an isolated real Anki profile.

The source of build settings is `project.yml`. XcodeGen includes native source files; the pre-build script produces the Rust static library for the selected simulator/device architecture. Linux/macOS XCTest covers core collection and replay operations. The macOS workflow builds UIKit and runs both native Anki and legacy UI tests. Public CI uses synthetic/upstream fixtures only. Optional local fixture tests operate on disposable copies and retain private data outside the checkout.
